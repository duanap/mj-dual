# 两人两杠起胡麻将联机版技术架构设计 V1.2（修订版）

## 一、项目定位

目标：

开发双人实时联机麻将小游戏。

第一阶段：

-   双人创建房间
-   实时联机对战
-   服务端权威控制牌局
-   不登录
-   不保存用户数据
-   不使用数据库

核心原则：

-   状态同步
-   规则引擎与网络层分离
-   内存状态管理

# 五、服务端权威原则

客户端只发送操作意图。

例如：

``` json
{
"type":"discard",
"card":"5筒"
}
```

服务器验证：

-   当前玩家
-   当前状态
-   是否拥有牌
-   是否允许操作

客户端不决定：

-   牌序
-   摸牌
-   胜负
-   胡牌结果

# 六、游戏状态机设计

## 房间生命周期

    WAITING_ROOM

    ↓

    DEALING

    ↓

    WAIT_CHOOSE_FLOWER

    ↓

    CHANGE_FLOWER

    ↓

    PLAYING_TURN

    ↓

    CHECK_ACTION

    ↓

    WAIT_CONFIRM_HU

    ↓

    SETTLEMENT

    ↓

    NEXT_ROUND

    ↓

    DEALING

------------------------------------------------------------------------

## 状态说明

### WAITING_ROOM

等待：

-   玩家加入
-   房间满员

------------------------------------------------------------------------

### DEALING

执行：

-   创建牌墙
-   洗牌
-   发牌

------------------------------------------------------------------------

### WAIT_CHOOSE_FLOWER

等待庄家：

    choose_flower

选择：

-   筒
-   条

超时：

自动选择手牌数量较多的花色。

------------------------------------------------------------------------

### CHANGE_FLOWER

执行：

-   花色交换
-   补牌
-   72张校验

完成：

-   庄家14张
-   闲家13张

------------------------------------------------------------------------

### PLAYING_TURN

回合循环：

    摸牌

    ↓

    暗杠/补杠/胡判断

    ↓

    出牌

    ↓

    对家响应

    ↓

    碰/杠/胡/过

    ↓

    进入下一回合

杠后补牌后返回当前玩家操作流程，支持连续杠。

------------------------------------------------------------------------

### CHECK_ACTION

检测：

-   碰
-   杠
-   胡
-   过

两人模式无需多人抢牌优先级。

------------------------------------------------------------------------

### WAIT_CONFIRM_HU

等待：

-   胡
-   放弃

------------------------------------------------------------------------

### SETTLEMENT

处理：

-   胜负
-   流局
-   本局结束

流局：

-   牌墙耗尽
-   杠后无法补牌

结果：

庄家继续坐庄。

------------------------------------------------------------------------

### NEXT_ROUND

等待：

-   双方 next_round_ready
-   或超时自动进入下一局

下一局重新：

    DEALING
    ↓
    发牌
    ↓
    定花

------------------------------------------------------------------------

# 九、联机工程要求

## 断线重连

创建房间生成：

-   roomId
-   playerToken

客户端：

localStorage保存。

重连：

携带token。

服务器返回：

当前玩家完整视角。

------------------------------------------------------------------------

## 超时规则

  等待点      默认行为
  ----------- ----------------------
  定花        自动选择手牌较多花色
  出牌        自动打出默认牌
  碰/杠响应   自动过
  胡确认      自动过

连续断线：

按超时规则继续托管完成本局。

------------------------------------------------------------------------

## 错误协议

# 十一、部署方案

    Nginx

    |

    Vue PWA


    /ws

    |

    Node.js游戏服务

注意：

客户端连接：

    wss://

代理路径：

    /ws

不是 `/wss`。

------------------------------------------------------------------------

要求：

-   HTTPS
-   WebSocket Upgrade
-   关闭proxy_buffering

现有：

EdgeOne + 雷池 + 宝塔链路。

要求：

-   WS域名/路径与现有游戏服务一致
-   EdgeOne放行WebSocket

------------------------------------------------------------------------

部署：

-   独立Node进程
-   systemd/pm2守护

内存态取舍：

进程重启：

-   房间消失
-   当前牌局结束

属于第一阶段设计选择。
